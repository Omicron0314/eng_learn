## 2. 产品方向

词间是以本地学习数据为中心的多端英语学习 App。入口顺序固定为：**今日、复习、文章、词库、生词箱、统计**；设置独立置于桌面导航底部，紧凑布局放顶部入口。

学习链路：导入自有词书 → FSRS 复习 → 用相关词生成文章 → 阅读或先听 → 点词标记 → 生词箱整理 → 后续复习与效果观察。首页展示今天可做的事；生成控制集中在文章页。数据优先留在设备，在线 AI 是可配置能力，缺少配置不阻塞离线复习。

## 3. 技术方向

- 共享 Rust 领域规则与应用服务，GPUI 渲染，gpui-kit-material 提供 M3 Expressive 外观；通过 gpui-kit facade 使用匹配的引擎类型。
- 桌面采用本地 SQLite、文件音频缓存、系统凭据存储与平台音频适配器。Rust 具体库和版本在 R00 验证后锁定。
- Web/WASM 复用可编译的领域与 UI 层，另做浏览器存储、音频、凭据和网络能力适配；不把桌面文件系统代码直接编译到浏览器。
- Android / iOS 原生先验证 GPUI 的渲染、输入、存储、音频与生命周期；验证不足时保留手机 Web 路线，不擅自改换 UI 框架。
- 多端首阶段各设备独立数据，可导出／恢复；同步有独立的后续协议任务。

上游已有桌面和 WASM 实现材料，但 Material 库自述为预发布且尚无组件通过独立生产验收。查阅证据见 [GPUI-FEASIBILITY](spikes/GPUI-FEASIBILITY.md)。本轮只做资料核实，没有编译或实机证明。

## 4. 保留与替代

保留：FSRS、确定性已知词集合、覆盖率分析、目标词／对照词、CSV/TXT/基础 APKG、语境释义缓存、阅读／听力分别反馈、事件审计、音频缓存与调用前配额预留、配置驱动 AI、已有原创 fixtures。

替代：Next.js 作为主产品架构、服务端专属密钥假设、浏览器作为所有端唯一免费朗读方案、首页生成器、正文遮挡式桌面点词弹层、旧 M0–M6 的任务状态。`prompts/*.v1.md` 是运行时资产，本轮不改其语义；未来变更有版本和评测。

## 5. 实施顺序与完成定义

先做 R00 平台／依赖验证，再建立 workspace、领域模型与存储、设计系统与壳层；随后导入／复习、分析／生成、阅读／整理／音频、首页／统计／设置，最后迁移工具、桌面验收、Web/WASM、移动原生验证和实现。详见 BACKLOG 的依赖图。

每项完成需要：规格对应的自动化证据；涉及 UI 的设计对照与交互证据；涉及数据的事务、事件、重启与失败证据。旧 Web 的测试通过数不能抵作 Rust 的验收。真实 AI 质量、实机平台能力与长期留存分别记录，不能由 mock 测试替代。
