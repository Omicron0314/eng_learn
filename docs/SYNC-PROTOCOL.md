# R21 同步协议草案 v1

状态：设计草案。R18 两端持久化验收及协议故障向量验证尚未完成，因此不标记 R21 完成；本文件不授权部署服务或传输真实学习数据。

## 范围与产品选择

同步必须由用户显式开启。首版选择可自托管的简单事件中继与版本化对象存储；托管服务是同协议的可选运营方式。暂不做商业账号、跨用户分享或协作词书。桌面与浏览器各自独立学习，断网不阻塞操作；冲突卡暂停继续评分，其他卡仍可学习。

传输 profile 学习设置、词书与成员、卡片历史、文章与目标、marks/inbox、阅读/听力完成和反馈。设备窗口、主题、播放速度不参与学习配置合并。provider 密钥、secret_ref、会话密钥、未完成模型任务、gloss 缓存和本地路径永不上传。公开 provider 地址/模型也默认留在本机，避免误把带内部主机名的配置广播给其他设备。

音频默认只同步内容清单，用户明确开启后才传 blob。远端模型调用记录和字符预留以产生请求的设备为准；同步可以汇总观察值，离线时不能声称全局预算严格不超额。严格全局付费额度需要在线授权租约，留给后续实现任务，不能用离线日志合并代替。

## 身份、权限与加密

profile 身份与登录账号分离；加入已有 profile 要获得其设备授权。每台设备有独立随机身份和撤销凭据，不从 MAC/硬件序列号推导。服务端按 profile 隔离访问，禁止仅凭对象 UUID 读取对象。

HTTPS 保护传输，服务端磁盘/备份加密保护静态数据；此方案的服务运营者能读取学习数据，产品必须明确说明。端到端加密尚未设计密钥恢复、撤销与浏览器保护，不把 TLS 宣传为端到端加密。自托管用户负责备份与证书更新，客户端不提供跳过 TLS 验证的默认选项。

## 事件封套和投递

封套包含 protocolVersion、profileId、deviceId、eventId、operationId、ordinal、entityId、entityVersion、parents、schemaVersion、payloadHash、payload、deviceSequence、observedAt、signature。签名覆盖固定规范编码后的整个封套；字符串不能因接收端 Unicode 规范化而改变原文。UUIDv7 用作身份，不用其时间部分决定业务先后。

同 eventId 同 payloadHash 重投直接确认；同 ID 不同 hash 拒绝并隔离，不覆盖既有事件。设备序号重复或倒退必须校验签名与已接收记录，不能静默重编号。引用尚未到达的 parent 进入 pending 区，不能猜测初始状态。

服务端为每个 profile 分配单调递增接收序号。拉取 cursor 表示已完整收到并落盘的连续前缀；客户端把 inbox 批次、业务事件、可重建投影与 cursor 在同一事务提交。事务失败不推进 cursor。服务端可以重复发送任意前缀，客户端不能因重复计数多建卡或多记评分。

设备时钟只提供显示时间和学习日证据，不决定覆盖顺序。需要同时保存发生时的时区/日界和服务端接收时间；时钟可疑的记录标注，而不是偷偷改掉原始 reviewed_at。学习日重新统计使用用户明确选择的规则。

## 冲突规则

### 同卡评分

每次评分携带完整 before 状态 hash、调度版本和 parent review eventId。接收端只在 before hash 与对应 parent 状态一致时认可该分支计算；不同调度版本没有转换器则阻塞，禁止重置卡片。

两个评分共享同一个 parent 时形成分叉：两个原始 review 事件都保留，卡片进入 conflict，不能用 updated_at 覆盖其中之一，也不能把原本各自离线的一次评分当成两次连续复习。展示两个分支供用户选择；在决议前，展示用的临时分支按 eventId 字节序选定，但禁止继续评分，实验统计把分叉及其依赖项列为 excluded。

resolve_review_conflict 事件引用全部冲突叶及用户选中的叶。只有包含全部已知冲突叶的决议才能恢复卡片；并发决议选择相同叶可合并，选择不同叶则产生新的待处理冲突。被拒分支及其后续离线评分保留为历史旁支，不伪造反向评分。新增迟到叶会重新打开冲突，不能因先前决议时间较新而丢弃。

### 词书、编辑和标记

词书成员使用带唯一 add 标签的 observed-remove 集合。删除只移除删除者已经见过的 add 标签，未见到的并发新增保留并提示。删除词书有 tombstone；并发编辑不会复活已删除词书，编辑保留于冲突记录。恢复必须创建显式 restore 事件。

卡片释义与例句按字段合并：修改不同字段可合并，同字段并发不同值保留双方并提示选择。不能因 AI 补全到得更晚覆盖用户编辑。暂停可与释义编辑独立合并；归档优先于普通恢复暂停，只有显式恢复归档事件可重新启用。

认识/不认识并发时保留不认识作为保守可用投影，并显示冲突；用户的新标记引用两个父版本后解除。pending inbox 以 profile×lexeme 聚合，一个待处理条目可关联多个来源上下文，不按重复投递新增多份。

阅读/听力完成按 sessionId 去重。反馈按 article×mode 分开；存在因果关系时取后继，无因果且不同值时保留冲突，不能把设备时钟较大当成最后意见。

## 备份、恢复与升级

备份恢复默认建立新 profile，不能拿旧 cursor 冒充原设备连续状态。用户明确恢复为同一同步身份时，生成新 deviceId，并先拉取服务端前缀再提交恢复来源记录；旧 eventId 仍保持，按 hash 去重。

协议只接受已支持的 major version。未知事件 schema 原封不动保存到隔离区，阻止受影响实体的投影更新并提示升级；不把它当成功应用。升级回滚保留原始事件文件及 checksum，不能下转换未知字段后覆盖。

服务端删除传播使用 tombstone 和设备确认水位。失联设备超过保留期后需要全量重新加入；垃圾回收前必须有可验证快照和恢复演练。撤销设备的后续上传拒绝，已同步历史仍保留来源。

## 必须通过的故障向量

| 场景 | 确定性结果 |
| --- | --- |
| 同一批次投递两次 | 一份事件、一份评分、cursor 到同一前缀 |
| child 比 parent 先到 | child pending；parent 落盘后再验证和应用 |
| 同 ID 不同 payload | 隔离并报错；已接收记录不变 |
| 同卡两端离线评分 | 两分支保留；卡片 conflict；不连续叠加 FSRS |
| 决议后收到第三个旧父评分 | 重新打开冲突；旧决议保留 |
| 删除词书同时修改释义 | 词书不复活；释义修改和来源保留 |
| 同词两个设备加入生词箱 | 一个 pending 投影，两个来源可追溯 |
| 上传成功但客户端确认前崩溃 | 重投后去重；不重复业务计数 |
| 应用事件过程中磁盘满 | 整批事务回滚，cursor 不变 |
| 设备时钟快两天 | 不凭时间覆盖；原时间与可疑标记保留 |
| 恢复旧备份后重连 | 新设备身份、旧事件 hash 去重、无 cursor 跳跃 |
| 离线两端同时合成音频 | 各设备本地额度各自生效；汇总不假装是全局授权 |

下一步是用 R18 的真实两端存储适配验证这些向量，再评估中继的认证、备份、流量和运维费用；在此之前不创建同步实现任务、不部署服务。
