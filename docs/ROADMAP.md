# 路线图

本轮完成文档重规划；以下是后续实施路线，不是既有交付。详细依赖见 [BACKLOG](BACKLOG.md)。

| 阶段 | 任务 | 交付与退出条件 |
| --- | --- | --- |
| G0 技术验证 | R00 | 最小消费者、Git依赖／patch、桌面与WASM能力证据、FSRS转换与存储方案；明确支持范围 |
| G1 基础 | R01–R05 | Rust workspace、纯领域与事务存储、M3主题／导航、可配置AI；空库可启动并操作 |
| G2 学习闭环 | R06–R12 | 导入→复习→生成→阅读／点词→生词整理→音频；错误路径与幂等全部有证据 |
| G3 完整桌面产品 | R13–R17 | 今日／热力图、统计、设置、迁移备份；设计稿全状态验收；逐OS打包和重启 |
| G4 Web与手机浏览器 | R18 | WASM共享界面与领域；浏览器存储、权限、离线、中文输入和移动触摸实测 |
| G5 移动原生 | R19→R20 | Android/iOS逐端验证后实施；未满足门槛的系统保持“未支持” |

G2各任务按依赖可形成小闭环，不要求一次替换全部旧Web。G3在Linux先完成可用版本，再以同等验收覆盖其他桌面平台；没有实机证据的系统明确阻塞，不写“已支持”。

## 体验验证

桌面闭环可用后开始2–4周自用，观察每周活跃、阅读完成、反馈、Again率与样本量，同时记录生成内容和系统朗读的主观问题。新框架性能与学习效果分别评价。

## 后续候选

逐句重复／听写、原创考试题型、内容导入、词汇初测、FSRS参数优化、输出练习与口语功能需单独规格。内置词书需要可分发许可；账号、托管AI和计费需要新的产品决定。它们不作为设计稿功能的隐含依赖。

## 变更约束

平台验证失败可以调整阶段顺序、保留可用端，但不静默移除设计稿功能或换掉用户指定的GPUI技术方向。旧代码退役以迁移／恢复与功能验收为条件，不以新工程能打开窗口为条件。
