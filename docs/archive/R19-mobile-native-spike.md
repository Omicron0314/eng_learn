# R19 · Android/iOS原生可行性验证

任务状态以 [BACKLOG](../BACKLOG.md) 为准。阶段：G5（远期，暂不实施）。依赖：R00。

## 目标与范围

逐系统建立最小GPUI/Material原型或记录无法建立的具体原因；结论写docs/spikes/R19-mobile.md。

设计追踪：screen-mobile以及平台生命周期。通用约定见 [specs/README](../specs/README.md)；未列出的后续功能不在本任务扩展。

## 验收标准

- **AC1**：核实是否有可维护的原生渲染后端及依赖链，记录revision／工具链／打包方式。
- **AC2**：真实设备验证触摸、中文IME、软键盘、屏幕旋转、前后台、GPU恢复和可访问性。
- **AC3**：验证数据库／文件选择／凭据／远端音频与系统朗读，说明与桌面的差异。
- **AC4**：给出Android、iOS各自go/no-go与成本范围；no-go不将浏览器截图当作原生完成。

## 验证与交付

可运行最小包与真机日志；缺环境或缺backend则证据化阻塞，不凭空填通过。

每条AC在交付记录中对应 CI 运行结果；本机用同一条命令复现用于排错，不单独作为验收证据（[D56](../DECISIONS.md)）。变更业务写入时同时断言events；失败路径检查不产生部分成功。

## 边界与风险

不得静默改换用户指定UI技术；备选栈只能作为后续提案，不能直接实施。

执行中发现设计或契约变化时更新 [DECISIONS](../DECISIONS.md) 和相应规格；没有实证的能力标未验证。
