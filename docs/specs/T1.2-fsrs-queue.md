# T1.2 FSRS 复习队列与评分

## 目标

封装 ts-fsrs,实现每日复习队列与 4 档评分;评分在一个事务内更新卡片、写 `review_logs` 与 `review` 事件。

## 范围与非范围

**范围**

- `packages/core/src/srs/`(纯逻辑):
  - `createSrs({ requestRetention })`:ts-fsrs 默认参数,`enable_fuzz: false`(保证可复现);
  - `rate(card, rating, now)` → 新卡片状态与日志数据;
  - `preview(card, now)` → 4 档各自的 `due` 与间隔,供界面显示;
  - `retrievability(card, now)` → 0–1,新卡为 0;
  - `buildQueue(input)` → 今日队列。
- 队列规则:
  1. 排除 `suspended` 卡片;
  2. 先放 `learning` / `relearning` 且 `due ≤ now` 的卡片,按 `due` 升序;
  3. 再放 `review` 且 `due ≤ now` 的卡片,按 `due` 升序,数量不超过 `dailyReviewLimit − 今日已复习数`;
  4. 最后放新卡,数量不超过 `dailyNewLimit − 今日已学新词数`;`origin` 为 `lookup` / `inbox` / `autoAdd` 的新卡优先(按 `created_at` 升序),其后是 `import` 新卡(按 `created_at` 升序)。
  - “今日已学新词数” = 今天 `state_before = new` 的 `review_logs` 条数;“今日已复习数” = 今天 `state_before = review` 的条数。“今天”按 `docs/specs/README.md` §3。
  - 因此点词加入的卡片优先占用当日新词名额,即“计入每日新词上限”。
- 仓储 `CardsRepo`:按用户读取队列所需字段、按 id 读取、更新调度字段。
- 服务 `reviewService.getQueue(deps)`、`reviewService.rate(deps, { cardId, rating, durationMs })`:`rate` 在一个事务内更新卡片(`updated_at`)、插入 `review_logs`(`state_before`、`due_before`)、追加 `review` 事件。
- API:`GET /api/review/queue`、`POST /api/review/rate`。

**非范围**:页面(T1.3);事件类型化与统计查询(T1.4);FSRS 参数优化。

## 接口

```ts
type Rating = "again" | "hard" | "good" | "easy";
type CardStateName = "new" | "learning" | "review" | "relearning";
type SrsCard = {
  due: Date; stability: number; difficulty: number; state: CardStateName;
  reps: number; lapses: number; lastReview: Date | null;
  scheduledDays: number; learningSteps: number;   // 以锁定的 ts-fsrs 版本字段为准
};
type QueueCard = { id: string; card: SrsCard; suspended: boolean; origin: CardOrigin; createdAt: Date };

function rate(card: SrsCard, rating: Rating, now: Date): { card: SrsCard; log: { stateBefore: CardStateName; dueBefore: Date } };
function preview(card: SrsCard, now: Date): Record<Rating, { due: Date; intervalMs: number }>;
function retrievability(card: SrsCard, now: Date): number;
function buildQueue(input: {
  cards: QueueCard[]; now: Date;
  dailyNewLimit: number; dailyReviewLimit: number;
  newIntroducedToday: number; reviewsDoneToday: number;
}): { learning: string[]; review: string[]; new: string[] };
```

## 验收标准

- AC1:对一张新卡,在固定 `now` 下分别评 4 档,`due` 满足 Again ≤ Hard ≤ Good ≤ Easy,且与直接调用 ts-fsrs 的结果一致(每档一条断言)。
- AC2:对一张 `review` 状态的卡片同样满足 AC1 的顺序;评 Again 后 `lapses` 加 1,状态变为 `relearning`。
- AC3:`retrievability` 在新卡上为 0;对刚复习的卡片接近 1,随时间单调下降。
- AC4:队列排除暂停卡片;`learning` 在 `review` 之前,`review` 在新卡之前。
- AC5:`dailyNewLimit=20`、今日已学 5 个新词时,队列最多 15 张新卡;复习上限同理。
- AC6:有 3 张 `origin=lookup` 和 30 张 `origin=import` 的新卡、名额 20 时,队列中的新卡以那 3 张开头,共 20 张。
- AC7:`rate` 后数据库中恰好新增 1 条 `review_logs` 与 1 条 `review` 事件,卡片调度字段已更新;事务中途失败时三者都不落库。
- AC8:对不存在或已暂停的卡片评分返回 `NOT_FOUND` / `VALIDATION_FAILED`,不写任何数据。
- AC9:日界:`dayStartHour=4` 时,凌晨 3 点的评分计入前一天的“今日已学”。

## 测试计划

- 单元:`srs` 模块(AC1–AC6、AC9),固定 `now`。
- 集成:`reviewService` 使用 `:memory:` 库(AC7、AC8)。

## 依赖与风险

- 依赖 T0.2。
- **待确认**:新增依赖 `ts-fsrs`(锁定版本;其 `Card` 字段决定 `cards` 表的列)。
- 风险:ts-fsrs 大版本之间字段与默认参数有变化,升级需走单独的提交与迁移。

## 审查修复验收

评分事务内用当前设置、日志和调度重新验证队列资格；新词 / review 名额不足和未来到期（含旧标签页重提）返回 VALIDATION_FAILED，不改变卡片、日志或事件。learning / relearning 按原规则不占 review 配额。
