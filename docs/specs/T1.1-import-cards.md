# T1.1 CSV 与基础 .apkg 导入

## 目标

把 CSV 或兼容格式的 `.apkg` 导入为复习卡片(新卡,归入指定牌组),为复习闭环提供数据。

## 范围与非范围

**范围**

- CSV 解析 `parseCardCsv(text)`(`packages/core/src/lexicon/csv.ts`,纯函数):
  - 列 `word,meaning,example`,后两列可选;首行若为表头(不区分大小写匹配 `word`)则跳过;
  - 支持 RFC 4180 引号(字段内逗号、换行、双引号转义);去 UTF-8 BOM;
  - 空 `word` 的行跳过并报告行号;文件内重复的词只取第一行,其余计为 `duplicates`。
- 编码:只接受 UTF-8;检测到非法 UTF-8 时返回 `VALIDATION_FAILED`,提示“请另存为 UTF-8”。
- `.apkg` 读取按 S2 结论实现于 `apps/web/src/server/import/apkg.ts`:兼容格式固定按模型字段名取 `Front` 为正面显示、`Back` 为背面释义并清洗 HTML(作者决定,2026-10-12;词条 key 仍是第一个字段,无字段名的牌组回退第一/第二字段);背面为空的词条留空,复习时由 T1.3 的 AI 释义兜底;`anki21b` 返回错误码 `APKG_UNSUPPORTED_FORMAT`,提示用户勾选“支持旧版 Anki”重新导出。
- 词的归一:`front` 保留原文(trim);词元 `lemma` = trim + 合并空格 + 小写,不做词形还原(导入的词本身就是词头)。
- 导入服务 `importCards(deps, { fileName, bytes, deck })`:一个事务内 upsert lexemes、创建卡片(`state=new`、`due=now`、`origin="import"`);同一用户已有该词的卡片时跳过,不覆盖;写 1 条 `import` 事件。
- `back_json`:`{ meaning?: string, example?: string, meaningSource: "import" | "ai" | "user" }`,有释义时为 `import`。
- API:`POST /api/import/cards`(multipart:`file`、`deck`),CSV 上限 20 MiB、.apkg 上限 64 MiB,超出返回 413。

**非范围**:页面(T1.3 的 `/library`);缺释义时的 AI 释义(T1.3);基线词表导入(T2.2);媒体与调度数据。

## 接口

```ts
type CardImportRow = { word: string; meaning?: string; example?: string; line: number };
function parseCardCsv(text: string): { rows: CardImportRow[]; errors: { line: number; reason: string }[]; duplicates: number };

type ImportResult = { added: number; skipped: number; duplicates: number; errors: { line: number; reason: string }[] };
function importCards(deps: AppDeps, input: { fileName: string; bytes: Uint8Array; deck: string }): Promise<ImportResult>;
```

## 验收标准

- AC1:导入 100 个不同词的 CSV,得到 100 张 `new` 卡片,`deck` 正确,`added=100`。
- AC2:再次导入同一文件:`added=0`、`skipped=100`,原卡片内容不变。
- AC3:文件内重复词(含大小写不同,如 `Apple` 与 `apple`)只建 1 张卡,`duplicates` 计数正确。
- AC4:引号字段内含逗号、换行、`""` 时解析正确;有 / 无表头均可;带 BOM 可解析。
- AC5:只有 `word` 列时也能导入,`back_json.meaning` 为空。
- AC6:空 `word` 行出现在 `errors` 中,带行号,不中断其余行。
- AC7:非 UTF-8 文件返回 `VALIDATION_FAILED`,不写任何数据。
- AC8:兼容格式 `.apkg` 样例导入后,正面 / 背面为清洗后的纯文本(S2 的清洗用例全部通过);模型字段名 Front 在非第一位置时也按其取正面。
- AC9:`anki21b` 样例返回 `APKG_UNSUPPORTED_FORMAT`,不写任何数据。
- AC10:每次导入恰好写 1 条 `import` 事件,payload 中的计数与返回值一致;导入失败时卡片与事件都不落库。

## 测试计划

- 单元:`parseCardCsv`、`stripAnkiHtml`(AC3–AC6、AC8 的清洗部分)。
- 集成:`importCards` 使用 `:memory:` 库与 `fixtures/csv/`、`fixtures/apkg/` 样例(AC1、AC2、AC7–AC10)。
- 样例 `fixtures/csv/words-100.csv` 由 agent 生成(常见英语词,不涉及版权)。

## 依赖与风险

- 依赖 T0.2、S2。
- **待确认**:CSV 解析推荐自实现(约 60 行),不引入 `papaparse`;解压库按 S2 结论(推荐 `fflate`)需确认新增依赖。
- 风险:国内用户的 CSV 常为 GBK 编码,MVP 只提示另存为 UTF-8;若作者的实际文件是 GBK,可考虑后续加编码检测。

## 上传边界审查修复验收

.apkg 压缩文件允许 64 MiB，CSV/TXT 仍为 20 MiB；multipart 总流 64 MiB + 64 KiB 元数据；proxy 缓冲高于该总流（65 MiB）。服务与路由分别按文件名检查边界，UI/文档一致；保留集合解压 100 MiB 限制。真实私有牌组只记录计数，不再分发或自动导入；默认/兼容双格式完整验收仍待验证。
