# T4.2 三按钮与 lookupMode

## 目标

实现弹层中的“认识 / 标记不认识 / 加入复习”,行为受设置项 `lookupMode` 控制。

## 范围与非范围

**范围**

- 服务 `markService`,每个操作一个事务:
  - **认识** `markKnown`:upsert `lexeme_marks`(`status=known`、`marked_at=now`),写 `mark_known` 事件。
  - **标记不认识** `markUnknown`:upsert `lexeme_marks`(`status=unknown`);然后
    - `markOnly`(默认):若该词没有 `pending` 的 inbox 行,新建一行(`context_sentence`、`article_id`);已有则不重复建。写 `mark_unknown` 事件(带 `inboxId`)。不建卡。
    - `autoAdd`:若该词没有卡片,建卡(`origin="autoAdd"`,`front=lemma`,释义取缓存中的语境释义,`meaningSource="ai"`);写 `mark_unknown`(带 `cardId`)与 `add_to_review`(`from="autoAdd"`)两条事件。
  - **加入复习** `addToReview`:若没有卡片则建卡(`origin="lookup"`);已有卡片且被暂停时恢复;写 `add_to_review` 事件(`from="lookup"`)。若该词有 `pending` 的 inbox 行,改为 `added`。
- 新建的卡片为 `new` 状态,按 T1.2 的规则优先占用当日新词名额。
- 弹层按钮调用对应 API 后显示结果(“已标记”、“已加入复习”、“已在复习中”)。
- API:`POST /api/marks`(`action: "known" | "unknown" | "add"`、`lemma`、`sentence`、`articleId?`)。

**非范围**:inbox 页面(T4.3);撤销操作。

## 接口

```ts
type MarkInput = { lemma: string; sentence: string; articleId?: string };
function markKnown(deps: AppDeps, input: MarkInput): void;
function markUnknown(deps: AppDeps, input: MarkInput): { inboxId?: string; cardId?: string };
function addToReview(deps: AppDeps, input: MarkInput): { cardId: string; created: boolean };
```

## 验收标准

- AC1:`markOnly` 下“标记不认识”只产生 1 条 `mark_unknown` 事件与 1 行 inbox,卡片数不变。
- AC2:同一词再次“标记不认识”不新增 inbox 行,仍写事件。
- AC3:`autoAdd` 下“标记不认识”建 1 张 `origin=autoAdd` 的卡片,释义来自语境释义缓存,写 `mark_unknown` 与 `add_to_review` 各 1 条。
- AC4:“加入复习”建卡并写 `add_to_review`;该卡出现在今日队列新卡部分的最前面;今日新卡总数仍不超过 `dailyNewLimit`(计入每日新词上限)。
- AC5:已有卡片时“加入复习”不重复建卡,返回 `created=false`;暂停的卡片被恢复。
- AC6:“加入复习”会把该词 `pending` 的 inbox 行改为 `added`。
- AC7:“认识”写 `lexeme_marks.status=known` 与 `mark_known` 事件;之后 T2.3 的已知集合包含该词。
- AC8:任一步骤失败时,该操作的标记、inbox、卡片、事件都不落库。

## 测试计划

- 集成:`markService`(AC1–AC8),`:memory:` 库。
- e2e:在 `lookup.spec.ts` 中补充三个按钮的点击流程(各断言一次界面反馈)。

## 依赖与风险

- 依赖 T4.1、T1.2、T2.3(AC7)。
- 风险:`autoAdd` 模式下点错也会建卡,界面需要清楚显示当前模式。

## Web 阶段实施证据与限制

三个按钮 UI 与回显经 E2E；markOnly / autoAdd、事务、日名额、幂等卡片由服务测试覆盖。 全栈命令与剩余证据缺口见 `docs/WEB-VALIDATION.md`。

点词弹层读取当前 lookupMode，显示当前模式；autoAdd 明确警告标记不认识会建卡并计入新词上限，动作成功按服务端 cardId/inboxId 显示实际结果。E2E 验证 autoAdd 通过设置启用、自动建卡、无 pending inbox。
