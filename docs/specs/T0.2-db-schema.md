# T0.2 Drizzle schema、迁移、仓储层基础

## 目标

建立全部数据表(`docs/DATA_MODEL.md` §1 加 §3 经确认的补充)、首个迁移、数据库连接与事务工具,以及跨任务共用的基础仓储。具体业务仓储(卡片、文章、inbox 等)由各自任务按需添加。

## 范围与非范围

**范围**

- `packages/db/src/schema.ts`:全部表的 Drizzle 定义。
- 迁移:`drizzle-kit generate` 生成到 `packages/db/migrations/`;另加一个自定义 SQL 迁移,为 `events`、`review_logs` 建立禁止 UPDATE / DELETE 的触发器。
- 连接:`openDb(path)` 打开 better-sqlite3,设置 `journal_mode=WAL`、`foreign_keys=ON`;`migrate(db)` 应用全部迁移,可重复执行。
- `newId()`:生成 UUIDv7(RFC 9562)。
- 事务:`withTx(db, fn)`,同步事务(better-sqlite3 为同步 API)。
- 基础仓储:
  - `UsersRepo.ensureDefaultUser()`:MVP 唯一用户,不存在则创建,返回其 id;
  - `SettingsRepo.get(userId)` / `update(userId, patch)`:经 `SettingsSchema` 校验,未存储时返回默认值(默认值见 `docs/specs/README.md` §4);
  - `EventsRepo.append(tx, { userId, type, payload })`:只有追加,没有更新、删除方法(T1.4 再加类型化校验);
  - `LexemesRepo.upsert(tx, { lemma, pos? })` / `findByLemma(lemma)`:`lemma` 先 trim 与小写化,`pos` 缺省为 `''`;
  - `LLMCallsRepo.insert(record)`。
- `SettingsSchema` 放在 `packages/core/src/settings.ts`(纯 zod,无 IO),db 与 web 共用。

**非范围**:业务仓储与服务;Postgres 支持。

## 接口

```ts
export type Db = BetterSQLite3Database<typeof schema>;
export function openDb(path: string): Db;            // ":memory:" 用于测试
export function migrate(db: Db): void;
export function newId(): string;                      // UUIDv7
export function withTx<T>(db: Db, fn: (tx: Tx) => T): T;

export interface Repos {
  users: UsersRepo;
  settings: SettingsRepo;
  events: EventsRepo;
  lexemes: LexemesRepo;
  llmCalls: LLMCallsRepo;
}
export function createRepos(db: Db): Repos;
```

## 验收标准

- AC1:对空库 `migrate` 成功;再执行一次不报错、不重复建表。
- AC2:迁移后,`DATA_MODEL.md` 中每张表与每个列都存在(测试读取 `sqlite_master` / `pragma table_info` 与期望清单比对)。
- AC3:`lexemes` 上 `(lemma, pos)` 唯一;`upsert` 同一词两次返回同一 id;`" Run "` 与 `"run"` 视为同一词。
- AC4:`cards` 上 `(user_id, lexeme_id)` 唯一;外键生效(插入不存在的 `lexeme_id` 失败)。
- AC5:对 `events`、`review_logs` 执行 UPDATE 或 DELETE 时数据库报错。
- AC6:`withTx` 内抛错时,事务内已写的事件与业务行都不落库。
- AC7:`newId()` 产生合法 UUIDv7(版本位 7、variant 位正确),同一毫秒内连续生成 1000 个,按字符串排序与生成顺序一致。
- AC8:`SettingsRepo.get` 在无记录时返回全部默认值;`update` 传入非法值(如 `dailyNewLimit: -1`)被拒绝且不写库;合法更新后再 `get` 能读到。
- AC9:用临时目录下的文件库写入数据、关闭、重新打开,数据仍在(对应 M1“重启后数据仍在”)。

## 测试计划

- 集成测试使用 `:memory:` 库并跑完全部迁移(AC1–AC8)。
- AC9 是唯一读写真实文件的测试,使用 `os.tmpdir()` 下的临时目录,结束后清理。

## 依赖与风险

**待确认(停下来问人)**

1. **新增依赖**:`drizzle-orm`、`drizzle-kit`(dev)、`better-sqlite3`、`@types/better-sqlite3`(dev)。UUIDv7 推荐自实现(约 30 行,用 `crypto.getRandomValues`),不引入 `uuidv7` 包。

**已确认**:`docs/DATA_MODEL.md` §3 的 schema 补充(2026-10-11)。

**风险**

- drizzle-kit 不生成触发器,触发器必须放在自定义 SQL 迁移里,且要保证 `migrate` 按顺序执行。
- better-sqlite3 需要原生编译;Docker 镜像要包含构建工具或使用预编译包。
- 本任务落地后迁移即视为“已合并”,之后只能新增迁移,不能修改。
