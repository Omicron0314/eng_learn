# T2.1 分词、词形还原、`analyzeText`

## 目标

实现确定性的文本分析:分词(带位置)、词形还原、跳过数字与专有名词、按 token 与按词种计算覆盖率,统计目标词出现次数。供文章生成(T3.2)、点词(T4.1)、评测(S3)使用。

## 范围与非范围

**范围**

- `packages/core/src/lexicon/tokenize.ts`:
  - 返回带字符偏移的 token:`word` / `number` / `punct`,以及句子序号、是否句首;
  - 弯引号 `’` 统一为 `'`;缩写作为一个 token(don't、I'm、they've、it's);
  - 连字符词作为一个 token(well-known);
  - 数字类:纯数字、`1990s`、`3rd`、`10:30`、`$5` 等标为 `number`。
- `Lemmatizer` 实现按 S1 结论,放在 `packages/core/src/lexicon/lemmatizer.ts`(数据文件若有,随包提供,不在运行时联网)。
- 功能词表 `FUNCTION_WORDS`(冠词、代词、介词、连词、助动词、情态动词等约 150 个),默认已知。
- 缩写:`n't`、`'m`、`'re`、`'ve`、`'ll`、`'d` 的缩写词按“主体 + 后缀”判断,主体为功能词或已知词即为已知;所有格 `'s` 去掉后再判断。
- 连字符词:整体词元已知,或每个部分都已知,即视为已知。
- 专有名词:句中(非句首)首字母大写的词视为专有名词并跳过,`I` 除外;LLM 返回的 `names` 中的词在任何位置都跳过(匹配不区分大小写)。
- `analyzeText`:按 plan 的 `AnalysisResult`,另加 `typeCoverage` 与 `unknownRatio`。
  - token 计数不含标点、数字、专有名词;
  - 已知判断:任一候选词元在 `known` 中、是目标词,或是功能词;
  - `targetOccurrences`:每个目标词元的出现次数(未出现记 0);
  - 空文本:`tokenCount=0`、`coverage=1`。
- 辅助:`sentenceAt(text, offset)` 返回包含该位置的句子文本(T4.1 用)。

**非范围**:多词短语匹配;词性标注(除非 S1 的方案需要);概率化已知模型。

## 接口

```ts
type Token = {
  surface: string; start: number; end: number;
  kind: "word" | "number" | "punct";
  sentenceIndex: number; isSentenceStart: boolean;
};
function tokenize(text: string): Token[];

interface KnownSet { has(lemma: string): boolean }
type AnalysisResult = {
  tokenCount: number;
  coverage: number;
  typeCoverage: number;
  unknownRatio: number;                          // 1 - coverage
  unknownLemmas: { lemma: string; count: number }[];   // 按 count 降序
  targetOccurrences: Record<string, number>;
  names: string[];
};
function analyzeText(
  text: string,
  known: KnownSet,
  opts: { lemmatizer: Lemmatizer; targets?: string[]; names?: string[] },
): AnalysisResult;
function sentenceAt(text: string, offset: number): string;
```

## 验收标准

- AC1(golden,缩写):`I don't think they've left.` 中 `don't`、`they've` 各计 1 个 token 且为已知;`left` 的候选包含 `leave` 与 `left`。
- AC2(golden,专有名词):`Yesterday Tom met Lucy in Paris.` 中 `Tom`、`Lucy`、`Paris` 被跳过并出现在 `names` 中;句首的 `Yesterday` 正常计数。
- AC3(golden,LLM names):`names: ["Mia"]` 时,句首的 `Mia` 也被跳过。
- AC4(golden,复数与时态):`children`→`child`、`went`→`go`、`studies`→`study`、`bigger`→`big`,在只有原形的已知集合下全部判为已知。
- AC5:数字类 token 不计入覆盖率;标点不计入。
- AC6:`targetOccurrences` 按词元计数(`decide`、`decided`、`decides` 都计入 `decide`),未出现的目标词为 0。
- AC7:`coverage` 与 `typeCoverage` 的计算在手工构造的样例上与手算一致。
- AC8:`fixtures/lemma/sentences.jsonl`(S1 数据)上,产品 `Lemmatizer` 的首个候选准确率不低于 S1 报告的值。
- AC9:对 `fixtures/analyzer/samples/` 下 20 篇样例文本,输出与快照一致(稳定性);同一输入多次运行结果相同。
- AC10:`sentenceAt` 对句中、句首、句末偏移都返回正确句子;支持 `.`、`?`、`!` 与引号内句末。
- AC11:`packages/core` 中本模块不读取文件(词形数据以 TS 模块形式导入),通过 T0.1 的边界检查。

## 测试计划

- 单元:`tokenize`、`analyzeText`、`sentenceAt` 全部为纯函数测试。
- golden 用例放 `fixtures/analyzer/golden/*.json`:`{ text, known, targets, names, expected }`。
- 20 篇样例文本由 agent 原创,用 Vitest 快照。

- 依赖 T0.1、S1。
