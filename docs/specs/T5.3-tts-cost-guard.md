# T5.3 成本护栏

## 目标

限制每日 TTS 合成字符数,超过上限时返回明确错误,避免费用失控。

## 范围与非范围

**范围**

- 护栏 `ttsBudget.check(deps, chars)`:今日已用 = 今天(`docs/specs/README.md` §3 的日界) `audio_reserve.chars` + 未关联 reservationId 的旧 `audio_generate.chars` 之和，与旧 `audios.chars` 总量取较大值（兼容历史数据、不重复计数）;若 `已用 + chars > ttsDailyCharLimit`,抛 `TTS_DAILY_LIMIT_EXCEEDED`(429),错误信息包含已用量、本次需要量与上限。
- 只在真正合成前检查;缓存命中不检查、不计数。
- `ttsDailyCharLimit = 0` 表示禁止服务端合成(只能用浏览器朗读)。
- 界面:超限时在播放器位置显示错误信息,并提供“改用浏览器朗读”按钮(切换到 T5.2 的 `browser` 模式)。
- `/settings` 已有 `ttsDailyCharLimit` 字段(T1.5);provider 状态旁显示今日已用 / 上限。

**非范围**:LLM 费用上限(MVP 只靠 `llm_calls` 记录与重试上限);按月预算。

## 接口

```ts
function getTtsUsage(deps: AppDeps): { usedChars: number; limit: number };
function checkTtsBudget(deps: AppDeps, chars: number): void;   // 超限抛 TTS_DAILY_LIMIT_EXCEEDED
```

## 验收标准

- AC1:上限 1000,今日已用 600,本次 400 → 放行(恰好等于上限);本次 401 → 拒绝。
- AC2:被拒绝时不调用 TTS、不写 blob、不写 `audios` 与事件。
- AC3:已超上限时,对已缓存的文章请求音频仍然成功。
- AC4:跨日界后用量归零(固定时钟,`dayStartHour=4`:3:59 仍算前一天,4:00 归零)。
- AC5:`ttsDailyCharLimit=0` 时所有服务端合成被拒绝。
- AC6(e2e):把上限设为很小的值后生成音频,页面显示超限信息与“改用浏览器朗读”按钮,点击后出现浏览器朗读控件。
- AC7:`/settings` 显示的今日已用量与 `getTtsUsage` 一致。

## 测试计划

- 集成:`checkTtsBudget` 与 `ensureAudio` 的组合(AC1–AC5、AC7)。
- e2e:在 `player.spec.ts` 中补充(AC6)。

## 依赖与风险

- 依赖 T5.1。
- 风险:本进程对不同哈希合成也串行检查并预留；多进程/多副本不在支持范围。失败保守预留可能高于真实费用，不退款。

## 审查修复验收

用量以调用前独立提交的 `audio_reserve` 事件为准；完整文本保守预留，部分合成 / provider 错误 / blob 错误 / 缓存事务失败均不退款。预留失败不调用 provider。缓存事件通过可选 reservationId 关联预留，兼容旧 audio_generate / audios 用量且不重复计费。测试注入以上失败并确认重试受配额限制；仅单进程支持并发串行。
