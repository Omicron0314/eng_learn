# S1 词形还原 spike

## 目标

在同一份标注数据上比较候选词形还原方案,选出 `Lemmatizer` 的 MVP 实现。词元级准确率目标 ≥95%。

## 范围与非范围

**范围**

- 标注数据:约 200 句英文,四级难度,风格接近生成文章(叙事、对话、独白)。句子由 agent 原创(不摘录受版权保护的文本),逐词标注词元,作者抽查至少 30 句。存为 `fixtures/lemma/sentences.jsonl`,T2.1 的 golden 测试直接复用。
- 覆盖类别(每类至少 20 个词次):规则复数、不规则复数(children、mice)、规则过去式 / 过去分词、不规则动词(went、been、caught)、-ing、比较级 / 最高级(better、biggest)、缩写(don't、I'm、they've)、所有格(Tom's)、连字符词(well-known)、同形异义(saw、left、leaves)。
- 候选方案:
  1. `wink-lemmatizer`(需要词性:比较“配合词性标注器”与“依次尝试名 / 动 / 形并取首个变化结果”两种用法);
  2. 离线词形表(如 AGID 的屈折变化表,或其他许可明确的词形表),查表 + 规则兜底;
  3. 纯规则基线(去 -s / -ed / -ing + 不规则表),作为下限参考。
- 指标:总体与分类别的词元准确率;对“已知判定”的影响(词元错但仍命中已知词表的比例);每千词耗时;包体积;许可证。

**非范围**:多词短语识别;产品代码。

## 接口

spike 确认产品使用的接口:

```ts
interface Lemmatizer {
  /** 输入小写单词,返回候选词元,按可能性从高到低;至少包含一个元素 */
  lemmas(word: string): string[];
}
```

返回多个候选的原因:`analyzeText` 判断“已知”时,任一候选在已知集合中即视为已知,降低同形异义造成的误判。

## 验收标准

- AC1:`fixtures/lemma/sentences.jsonl` 不少于 200 句,每个类别不少于 20 个词次,标注格式为 `{ text, tokens: [{ surface, lemma }] }`。
- AC2:`spikes/S1/run.ts` 在同一数据上输出每个候选的总体与分类别准确率;重复运行结果一致。
- AC3:`docs/spikes/S1.md` 包含结果表、推荐方案与理由、许可证核实结论;若推荐方案带数据文件,同时写入 `docs/licenses.md`。
- AC4:推荐方案在“首个候选”口径下总体准确率 ≥95%;如果都达不到,S1.md 写明差距最大的类别和补救办法(如补充不规则表),交作者决定。

## 测试计划

spike 不要求单元测试;数据集本身在 T2.1 中转为 golden 测试。

## 依赖与风险

**待确认(停下来问人)**

1. 候选库(`wink-lemmatizer`、可能的词性标注器)装在 `spikes/S1/` 下;选定方案进入产品时再确认依赖。
2. 离线词形表的许可证必须核实后才能放进仓库。

**风险**:标注由 agent 完成,可能有系统性偏差;作者抽查不通过时需重新标注相关类别。
