# R21 · 跨端同步协议设计

任务状态以 [BACKLOG](../BACKLOG.md) 为准。阶段：G6。依赖：R18。

## 目标与范围

只做协议与冲突规格：profile/device身份、事件传输、cursor、幂等、删除传播、同卡并发评分与恢复；实现需后续新任务。桌面与Web即可提供两端验证基础，不等待移动原生可行性；R20通过后再加入相应平台。

设计追踪：设计稿未覆盖的新能力，独立规划。通用约定见 [specs/README](README.md)；未列出的后续功能不在本任务扩展。

## 验收标准

- **AC1**：明确同步的实体、凭据排除、加密／认证边界与离线变更路径。
- **AC2**：用同卡两端离线评分、删书／编辑冲突、重复乱序投递定义确定性结果；不用last-updated简单覆盖调度。
- **AC3**：备份／恢复／设备时钟偏差／协议升级有可测试情景，指标与配额是否跨端汇总明确。
- **AC4**：评估服务器／自托管选项与代价，记录产品决定后才创建实现规格。

## 验证与交付

协议状态机、冲突向量与故障场景评审；不在本任务部署同步服务。

每条AC在交付记录中对应测试、截图或平台运行证据；需要实机的条目不可用静态审查抵替。变更业务写入时同时断言events；失败路径检查不产生部分成功。

## 边界与风险

多端与同步不同；UUIDv7、append-only和时间戳只是基础，不足以保证一致性。

执行中发现设计或契约变化时更新 [DECISIONS](../DECISIONS.md) 和相应规格；没有实证的能力标未验证。
