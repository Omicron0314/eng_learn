# T3.2 `generateArticle`(含重试)

## 目标

把选词、提示词、LLM、校验、分析、重试、落库串成确定性的文章生成工作流。

## 范围与非范围

**范围**

- 服务 `generationService.generateArticle(deps, { tier?, genre? })`,步骤:
  1. `selectTargetsForUser`;为空时返回 `NO_TARGETS`(400)。
  2. 体裁:未指定时在 story / dialogue / monologue 中选最近最少使用的一种。
  3. 用 `prompts/article.v1.md` 与 `renderArticlePrompt` 构建提示词;只把 exposed 词放进 `targets`,control 词不出现在提示词中。
  4. `completeJson`,schema 为 `{ title: string(min 1), body: string(min 1), names: string[] }`;每次底层调用写一行 `llm_calls`(purpose `article`)。
  5. `getKnownSet({ targets: exposed })` → `analyzeText(body, known, { targets: exposed ∪ control, names })`。
  6. 若 `coverage` 低于档位下限(easy 0.98 / medium 0.95 / hard 0.90),把 `unknownLemmas` 中排除目标词后的前 10 个作为 `avoidWords` 重新生成;最多重试 `settings.generationMaxRetries` 次(默认 1)。
  7. 所有尝试中取 `coverage` 最高的一次;全部低于下限时 `belowTier = true`。
  8. 一个事务内落库:`articles`(`kind="generated"`、`source="llm"`、`license=null`、`prompt_version="article.v1"`、`model` 取 LLM 返回值、`level_tier`、`genre`、`analysis_json`)、`article_targets`(exposed 与 control 各一行,`occurrences` 为实际出现次数)、`article_generate` 事件。
  9. 返回 `{ articleId, coverage, belowTier, missingTargets }`。
- 目标词缺失:exposed 词出现 0 次时列入 `missingTargets`(存进 `analysis_json`),不额外重试(需要改提示词才能要求补词,属于提示词变更)。
- 修复重试(JSON 非法)与 coverage 重试分开计数:前者由 `completeJson` 内部处理,最多 1 次。
- `analysis_json`:`AnalysisResult` 全部字段 + `wordCount`、`attempts: [{ coverage, avoidWords }]`、`missingTargets`、`belowTier`。
- API:`POST /api/articles`(body:`tier?`、`genre?`)。

**非范围**:多轮“生成-校验-重写”(Phase 2);文章页面(T3.3)。

## 接口

```ts
type Tier = "easy" | "medium" | "hard";
type Genre = "story" | "dialogue" | "monologue";
function generateArticle(deps: AppDeps, input: { tier?: Tier; genre?: Genre }): Promise<{
  articleId: string; coverage: number; belowTier: boolean; missingTargets: string[];
}>;
const TIER_MIN_COVERAGE: Record<Tier, number> = { easy: 0.98, medium: 0.95, hard: 0.9 };
```

## 验收标准

以下全部使用 FakeLLM 与 `:memory:` 库。

- AC1(正常):1 次 LLM 调用,1 篇文章,`article_targets` 行数 = exposed + control,1 条 `article_generate` 事件,1 行 `llm_calls`(`status=ok`,`model` 为 FakeLLM 返回的模型名)。
- AC2(JSON 非法 → 修复成功):2 行 `llm_calls`(`invalid_output`、`ok`),文章正常落库。
- AC3(JSON 两次非法):返回 `LLM_OUTPUT_INVALID`,2 行 `invalid_output`,没有文章、`article_targets` 与事件。
- AC4(coverage 不足):第一次回复 coverage 低于下限,第二次请求的提示词包含 `Do NOT use these words:` 和第一次的未知词(不含目标词);最终保存 coverage 较高的一次。
- AC5(重试上限):两次都低于下限时只调用 2 次(`generationMaxRetries=1`),保存较好的一次,`belowTier=true`。
- AC6(目标词缺失):回复中缺少某个 exposed 词,该词的 `occurrences=0` 且出现在 `missingTargets` 中,不触发额外调用。
- AC7:control 词不出现在任何一次提示词中;若回复中意外出现,`occurrences` 记录实际次数。
- AC8:提示词与代码中没有模型名(T0.1 的边界检查);`articles.prompt_version = "article.v1"`。
- AC9:没有可选目标词时返回 `NO_TARGETS`,不调用 LLM。

## 测试计划

集成测试覆盖 AC1–AC9;FakeLLM 回复放在 `fixtures/llm/article/*.json`,包含合法、非法、低覆盖、缺词四种。

## 依赖与风险

- 依赖 T3.1、T0.3、S3。
- 风险:取 coverage 最高的一次可能牺牲文章质量;自用阶段通过“不自然”标记观察。

## 审查修复验收

AC7 同样适用于非法 JSON 修复：向模型发送前须过滤回复和诊断中的 control 词，不改变原始调用日志。增加非法输出含 control 的回归；提示词文件语义保持不变。
