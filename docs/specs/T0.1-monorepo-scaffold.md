# T0.1 monorepo、lint、测试、CI、部署骨架

## 目标

搭好 pnpm monorepo 与工程基线,让后续任务可以直接写代码、写测试、跑 CI。完成后 `pnpm test`、`pnpm lint`、`pnpm typecheck`、`pnpm e2e` 均可运行且全绿。

## 范围与非范围

**范围**

- pnpm workspace:`packages/core`、`packages/providers`、`packages/db`、`apps/web`,包名 `@eng-learn/<name>`。内部包以 TS 源码形式被 `apps/web` 引用(Next.js `transpilePackages`),不单独构建。
- TypeScript:根 `tsconfig.base.json`,开启 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`。
- lint / format:Biome(已定,见 `docs/DECISIONS.md`)。
- Vitest:根配置 + 各包 project;Playwright:`apps/web/e2e`,只装 chromium。
- Next.js(App Router)+ Tailwind + shadcn/ui 初始化(`components.json` 与 `cn` 工具);`/` 重定向到 `/today`,`/today` 先放占位页。
- PWA manifest:`app/manifest.ts`,名称、主题色、占位图标。
- `APP_PASSWORD`:设置后,Next.js middleware 拦截所有页面与 API,未登录跳转 `/login`;登录成功写 httpOnly cookie(值为 `HMAC(APP_PASSWORD, "session")`),比较用常量时间。未设置时不拦截。
- `.env.example`:按 `docs/specs/README.md` §5 列出全部变量,只放占位符。
- 边界检查脚本 `tools/check-boundaries.ts`(随 `pnpm lint` 运行):
  - `packages/core` 不得 import `node:fs`、`fs`、`node:net`、`node:http`、`better-sqlite3`、`@eng-learn/db`、`@eng-learn/providers`,不得出现 `fetch(`、`Date.now(`、`Math.random(`;
  - 仓库代码与提示词(排除 `docs/`、`tools/eval/results/`)中不得出现形如 `/\b(gpt|claude|gemini|deepseek|qwen|glm)-[\w.]+/i` 的模型名。
- GitHub Actions `ci.yml`:install(`--frozen-lockfile`)→ lint → typecheck → test → e2e。
- 部署:`Dockerfile`(Next.js standalone 输出,多阶段构建)、`docker-compose.yml`(单服务,`./data:/app/data` 数据卷,`env_file: .env`)。
- `.nvmrc`(Node 24)、`package.json` 的 `packageManager` 字段锁定 pnpm 版本。

**非范围**:数据库(T0.2)、providers(T0.3)、任何业务页面。不添加 LICENSE,`package.json` 不写 `license` 字段。

## 接口

根 `package.json` scripts:

```
dev        -> pnpm --filter @eng-learn/web dev
build      -> pnpm --filter @eng-learn/web build
test       -> vitest run
lint       -> <lint 工具> && tsx tools/check-boundaries.ts
typecheck  -> pnpm -r typecheck        # 各包 tsc --noEmit
e2e        -> pnpm --filter @eng-learn/web e2e
```

`eval:generation`、`report:experiment` 由 S3、T6.2 添加。

## 验收标准

- AC1:全新克隆后 `pnpm install && pnpm lint && pnpm typecheck && pnpm test` 全部成功(每个包至少一个示例测试)。
- AC2:`pnpm e2e` 冒烟测试通过:打开 `/` 后落在 `/today`,页面返回 200 且有标题。
- AC3:`GET /manifest.webmanifest` 返回 200,JSON 含 `name`、`start_url`、`display: "standalone"`。
- AC4:设置 `APP_PASSWORD` 时,未登录访问 `/today` 跳转 `/login`,访问 `/api/*` 返回 401;输错密码停留在登录页;输对后可访问。未设置时直接可访问。
- AC5:边界检查能拦住违规:在测试中对含 `import fs from "node:fs"` 的 core 文件、含 `Math.random(` 的 core 文件、含模型名的提示词文件分别运行检查,均返回非零退出码。
- AC6:CI workflow 文件存在且步骤与上文一致(在远程仓库确定前,至少用 `act` 或人工检查确认语法;托管确定后以首次 CI 通过为准)。CI 的 E2E 使用此前 `pnpm build` 的生产服务，避免开发模式首次按需编译占用交互断言时间；本地 E2E 保留 dev 服务。失败时上传 Playwright trace / error context，保留 7 天。
- AC7:`docker compose config` 校验通过;`docker build` 成功(本地或 CI 中执行一次)。

## 部署审查修复验收

写请求同源校验使用浏览器 Host 与实际协议，不以 standalone 监听地址为来源；不信任 Forwarded/X-Forwarded-*。反向代理使用显式 APP_ORIGIN（仅 http/https origin、无用户名/路径/查询），启动校验，HTTPS 配置启用 Secure cookie。离线启动 HOSTNAME=0.0.0.0 的 standalone：真实浏览器 Origin 可登录/写入、跨站拒绝、显式 HTTPS public origin 可用。
