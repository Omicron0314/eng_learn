# T4.3 `/inbox`

## 目标

集中处理阅读中标记的生词:批量加入复习或忽略。

## 范围与非范围

**范围**

- 列表:`pending` 状态的 inbox 行,显示词元、语境句(高亮该词)、来源文章链接、标记时间、缓存的语境释义(有则显示);按时间倒序。
- 多选(含全选)后:
  - **加入复习**:对每一行按 T4.2 的 `addToReview` 规则建卡(`origin="inbox"`,`from="inbox"`),行状态改为 `added`;
  - **忽略**:行状态改为 `ignored`,写 `inbox_ignore` 事件。
- 批量操作在一个事务内完成,每行各写一条事件。
- 导航栏显示 `pending` 数量。
- API:`GET /api/inbox`、`POST /api/inbox/batch`(`action: "add" | "ignore"`、`ids`)。

**非范围**:inbox 内编辑释义;已忽略条目的恢复界面。

## 接口

```ts
function listInbox(deps: AppDeps): {
  id: string; lemma: string; sentence: string; articleId: string | null; createdAt: number; gloss?: Gloss;
}[];
function batchInbox(deps: AppDeps, input: { action: "add" | "ignore"; ids: string[] }): { processed: number; cardsCreated: number };
```

## 验收标准

- AC1:3 行 `pending`,选 2 行加入复习:新增 2 张 `origin=inbox` 的卡片、2 条 `add_to_review` 事件,这 2 行变为 `added`,列表只剩 1 行。
- AC2:忽略 1 行:状态变为 `ignored`,1 条 `inbox_ignore` 事件,不建卡;该行不再显示。
- AC3:某行的词已有卡片时,加入复习不重复建卡,行状态仍改为 `added`,`cardsCreated` 不计入。
- AC4:传入不存在或非 `pending` 的 id 时整批拒绝(`VALIDATION_FAILED`),不写任何数据。
- AC5:导航栏 `pending` 数量与列表一致,操作后更新。
- AC6(e2e):在文章页标记 2 个生词 → `/inbox` 显示 2 行 → 全选加入复习 → `/review` 队列新卡部分以这 2 个词开头。

## 测试计划

- e2e:`inbox.spec.ts`(AC6)。
