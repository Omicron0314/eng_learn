# T3.3 `/article/[id]` 页面

## 目标

展示生成的文章,正文按 token 渲染以支持点词(T4.1),记录打开与读完事件(H1 的完成率)。

## 范围与非范围

**范围**

- 页面内容:标题;元信息(体裁、档位、coverage 百分比、生成时间;`belowTier` 时显示“比所选档位更难”);正文按段落渲染。
- 正文渲染:服务端用 `tokenize` 切分,`word` token 渲染为带 `data-start`、`data-end`、`data-sentence` 属性的 `<span>`,点击行为由 T4.1 接入;非 word token 原样输出,保留原文空白与换行。
- 预留位置:音频播放器(T5.2)、难度反馈与“不自然”标记(T6.1)。
- 事件:
  - 页面加载时写 `article_open`;
  - 文末“读完了”按钮写 `article_complete`(`via="button"`);滚动到文末且停留 ≥3 秒时自动写一次 `article_complete`(`via="scroll"`);一次打开最多记一次。
- 文章不存在时返回 404 页面。
- API:`POST /api/articles/[id]/events`(类型限 `article_open`、`article_complete`)。

**非范围**:点词弹层(T4.1);目标词高亮;文章列表(在 `/today` 展示)。

## 接口

```ts
function getArticleView(deps: AppDeps, articleId: string): {
  id: string; title: string; genre: Genre; tier: Tier; coverage: number; belowTier: boolean;
  createdAt: number; paragraphs: { tokens: Token[]; text: string }[];
} | null;
function recordArticleEvent(deps: AppDeps, input: { articleId: string; type: "article_open" | "article_complete"; via?: "button" | "scroll" }): void;
```

## 验收标准

- AC1(e2e):FakeLLM 生成文章后打开页面,标题与正文可见;页面上 `span[data-start]` 的数量等于正文中 `word` token 的数量。
- AC2:正文渲染后的纯文本与原文一致(空白与标点不丢)。
- AC3:打开页面写 1 条 `article_open` 事件。
- AC4:点击“读完了”写 1 条 `article_complete`(`via="button"`);再次点击不重复记录;滚动到底已自动记录后,点击按钮也不再记录。
- AC5:不存在的 id 显示 404。
- AC6:`belowTier` 的文章显示提示文字。

## 测试计划

- 单元:段落切分与 token 渲染辅助函数(AC2)。
- 集成:`recordArticleEvent` 的校验与去重(AC4 的服务端部分)。
- e2e:`article.spec.ts`(AC1、AC3–AC6)。

## 依赖与风险

- 依赖 T3.2。
- 风险:滚动自动记录在短文章或大屏上可能一打开就触发,所以要求停留 3 秒;统计时可按 `via` 分开看。

## Web 阶段实施证据与限制

E2E 验证生成后的标题 / 正文、文本与原文一致、可键盘触发词 span、读完反馈、404。打开 / 完成事件及 openId 去重经 service / route 测试；按钮与滚动 ≥3 秒自动完成均由 E2E 验证。 全栈命令与剩余证据缺口见 `docs/WEB-VALIDATION.md`。
